# 电商运营助手需求说明

## 1. 项目概述

### 1.1 项目目标

建设一个面向电商运营团队的智能运营工作台，以单品经营全生命周期为核心，形成以下可追溯闭环：

`商品建档 -> 竞品录入 -> 智能诊断 -> 创意方案 -> 异步素材生成 -> 素材审核 -> 投放实验建议 -> 人工审批 -> 经营数据回填 -> 复盘报告 -> 下一轮迭代`

系统通过结构化数据、AI 辅助生成、异步任务和人工审核降低运营人员的重复工作，但不替代运营人员作最终业务决策。

### 1.2 一期成功标准

- 能围绕同一商品完整串联诊断、创意、素材、投放建议和复盘数据。
- AI 生成内容结构完整、可编辑、可保存版本，并明确标识生成来源。
- 图片和视频任务可以排队、执行、取消、超时、失败和重试。
- 投放建议和素材必须经过人工审核，审批过程可追溯。
- 经营指标采用统一口径，复盘结论能够追溯到输入数据。
- 无第三方服务密钥时，也能通过模拟服务完成端到端演示。

## 2. 一期范围与边界

### 2.1 本期范围

- 单组织、多店铺、平台商品映射和多规格 SKU 管理。
- SKU 库存维护及阈值预警。
- 商品、竞品、SKU、库存和经营数据的手工录入及 Excel/CSV 导入。
- 基于大语言模型的商品诊断、主图方案和短视频脚本生成。
- 通过异步任务调用图片及视频生成服务。
- 素材版本、标签、审核和归档管理。
- 投放实验建议生成、人工审批和外部执行备注。
- 经营数据回填、指标计算及单品复盘报告。
- 用户、角色、店铺授权、模型服务和任务规则配置。
- 操作审计、异常提示、演示数据和完整演示链路。

### 2.2 本期不包含

- 淘宝、京东、抖音等平台商品、订单、库存或经营数据的实时同步。
- 竞品网页自动抓取、反爬处理及未经授权的数据采集。
- 外部广告账户的计划创建、自动投放、自动调价或资金扣费。
- ERP、WMS、CRM、财务系统等企业系统集成。
- 面向消费者的商城、交易和支付功能。
- SaaS 多租户计费、原生移动应用和确定性的销量效果承诺。

### 2.3 明确约定

1. 一期“多平台接入”指维护平台、店铺、外部商品编号和 SKU 映射，不代表实际调用平台开放接口。
2. 竞品公开数据由用户录入或导入，并记录来源链接和采集时间；系统不主动抓取。
3. 语言、图片和视频模型通过可配置适配器接入；交付时同时提供离线模拟服务。
4. 默认时区为 `Asia/Shanghai`，默认币种为人民币 `CNY`。
5. 系统只做基于已录入数据的对比分析，不对数据不足的情况输出确定性因果归因。
6. 所有面向投放或公开使用的 AI 内容都必须经过人工确认。

## 3. 用户角色

| 能力 | 运营人员 | 运营主管 | 系统管理员 |
| --- | --- | --- | --- |
| 维护商品、SKU 和竞品 | 是 | 是 | 是 |
| 发起诊断、创意和素材任务 | 是 | 是 | 是 |
| 编辑 AI 内容 | 是 | 是 | 是 |
| 提交素材审核 | 是 | 是 | 是 |
| 审核素材 | 否 | 是 | 是 |
| 创建投放建议草稿 | 是 | 是 | 是 |
| 批准或驳回投放建议 | 否 | 是 | 是 |
| 回填经营数据、查看报告 | 是 | 是 | 是 |
| 管理用户和店铺授权 | 否 | 否 | 是 |
| 配置模型、队列和安全参数 | 否 | 否 | 是 |
| 查看全量审计日志 | 否 | 否 | 是 |

用户只能访问获授权店铺的数据。运营人员不能批准自己提交的投放建议。服务配置中的密钥只能写入或替换，不能在页面中完整回显。

## 4. 核心业务对象

| 对象 | 定义 |
| --- | --- |
| 店铺 | 归属一个平台，一个店铺包含多个商品 |
| 商品（SPU） | 单品运营主对象，可映射多个平台商品并包含多个 SKU |
| SKU | 商品销售规格，包含规格、价格、库存和预警阈值 |
| 平台商品映射 | 商品在具体平台和店铺中的外部商品编号、链接及 SKU 对应关系 |
| 竞品 | 与商品关联的对标对象，包含来源、价格、参数、卖点和采集时间 |
| 诊断轮次 | 一次商品诊断及其输入快照、结构化结论和版本 |
| 创意方案 | 基于诊断生成的主图方向或视频脚本，可保存多个版本 |
| 生成任务 | 图片或视频异步生成记录，包含执行状态和重试历史 |
| 素材 | 生成或上传的图片、视频及其版本、标签和审核记录 |
| 投放实验建议 | 人群、预算、出价、素材组合、实验周期、停止条件和目标指标 |
| 经营数据 | 按日期、店铺、平台商品及可选 SKU/实验记录的基础指标 |
| 复盘报告 | 目标与实际对比、数据限制、差异说明和后续行动项 |
| 审计日志 | 关键操作的操作者、对象、时间、动作及结果 |

所有业务对象均记录唯一 ID、创建人、创建时间、修改人和修改时间。被报告或审批记录引用的数据只能归档，不得直接物理删除。

## 5. 功能需求

### 5.1 店铺、商品和库存

- 支持店铺创建、编辑、停用和归档。
- 支持商品创建、编辑、检索、筛选和归档。
- 商品状态包括草稿、在售、停售和归档。
- 支持一个商品维护多个 SKU，店铺内 SKU 编码唯一。
- SKU 至少包含规格属性、销售价、可用库存和预警阈值。
- 可用库存小于或等于预警阈值时触发库存预警。
- 支持维护商品在多个店铺或平台中的商品编号、链接和 SKU 映射。

### 5.2 竞品和智能诊断

- 支持手工录入和批量导入竞品。
- 竞品至少包含名称、平台、来源链接、价格、核心参数、主要卖点和采集时间。
- 发起诊断时保存商品、SKU 和竞品输入快照，源数据变化不得改写历史诊断。
- 诊断必须包含目标客群、价格带分析、卖点矩阵、竞品差异、转化卡点、风险提示和优化方向。
- 诊断结果可以在线编辑、确认、归档和保存版本，原始 AI 输出不得覆盖。
- 复盘行动项可以转入下一轮诊断，并保留来源报告链接。

### 5.3 创意方案和脚本

- 每次至少生成 3 组差异化主图方案。
- 每组主图方案包含方向名称、目标客群、构图、核心文案、主打卖点、色彩和视觉元素建议。
- 每次至少生成 3 套短视频分镜脚本。
- 每套脚本包含建议时长、开头 3 秒钩子、逐镜画面、镜头时长、口播、字幕和促单话术。
- 主图方案和脚本支持编辑、复制、版本对比、确认和归档。
- 系统对明显的禁用词、绝对化宣传和敏感内容给出风险提示。

### 5.4 异步生成任务

- 图片和视频生成必须通过异步任务处理，不阻塞普通业务请求。
- 任务状态为 `pending`、`running`、`cancelling`、`cancelled`、`succeeded`、`failed`、`timed_out`。
- 失败或超时任务允许人工重试，每次重试保留独立执行记录。
- 默认最多重试 3 次；图片任务默认 5 分钟超时，视频任务默认 30 分钟超时，管理员可配置。
- 重复提交使用幂等控制，防止连续点击创建重复付费任务。
- 状态变化后 5 秒内应反馈到页面。
- 模拟服务必须支持成功、失败、超时和取消四类验收场景。

### 5.5 素材库

- 生成成功的文件自动进入对应商品素材库，也支持上传自有素材。
- 素材状态为草稿、待审核、已通过、已驳回和已归档。
- 素材支持标签、版本、来源方案、生成参数、尺寸、时长和审核记录查询。
- 运营主管负责审核素材，驳回时必须填写原因。
- 只有审核通过的素材可以加入已批准的投放实验建议。

### 5.6 投放实验建议

- 建议包含实验目标、目标人群、渠道、预算区间、出价、素材组合、A/B 变量、周期、停止条件和目标指标。
- 目标指标至少支持曝光量、点击率、转化率、GMV 和 ROI。
- 状态为草稿、待审批、已批准、已驳回和已结束。
- 运营人员编辑并提交建议，运营主管批准或驳回；驳回必须填写原因。
- 审批记录包含版本、提交人、审批人、时间、意见和结果。
- 系统仅记录外部人工执行时间和备注，不调用广告平台接口。

### 5.7 经营数据

- 最小数据粒度为“日期 + 店铺 + 平台商品”，可选关联 SKU 和投放实验。
- 基础字段包括曝光量、点击量、访客数、跳失访客数、支付订单数、销售件数、GMV 和广告花费。
- 系统统一计算：
  - `CTR = 点击量 / 曝光量`
  - `CVR = 支付订单数 / 点击量`
  - `跳失率 = 跳失访客数 / 访客数`
  - `ROI = GMV / 广告花费`
- 分母为 0 时指标显示 `--`。
- 同一粒度重复录入时，必须提示覆盖并记录修改前后的值。

### 5.8 经营复盘

- 用户选择商品、已审批实验和统计周期后生成报告。
- 报告包含单品信息、诊断与创意摘要、实验目标、审批记录、目标与实际对比、指标趋势、差异说明、数据限制和行动项。
- 事实数据必须来自系统记录，AI 解释必须单独标识。
- 数据不足时明确显示“数据不足”，不得生成确定性结论。
- 报告支持在线预览、版本保存和 Markdown 导出。

### 5.9 运营大盘

- 支持按日期、平台和店铺筛选。
- 展示商品总数、在售数、动销率、库存预警 SKU 数、GMV、广告花费、CTR、CVR 和 ROI。
- 动销率定义为统计周期内有支付订单的在售商品数 / 在售商品总数。
- 展示指标趋势、库存预警、失败任务和待审批事项。
- 无数据、加载中、加载失败和无权限状态必须有明确反馈。

### 5.10 批量导入

- 支持商品、SKU 与库存、竞品、经营数据四类模板。
- 支持 XLSX 和 UTF-8 CSV，单文件不超过 10 MB、10,000 行。
- 流程为上传、字段映射、数据校验、预览、确认、执行和结果报告。
- 校验必填项、类型、枚举、唯一键、关联对象和数值范围。
- 默认采用部分成功模式，合法行写入，非法行拒绝。
- 结果展示新增、更新、跳过和失败数量；错误明细可以下载。

### 5.11 系统配置和审计

- 管理员可配置语言模型、图片及视频服务的地址、模型、密钥、超时和启用状态。
- 支持配置任务并发数、超时时间和最大重试次数。
- 密钥必须加密存储并掩码显示。
- 素材审核、投放审批、导入、服务配置等关键操作必须进入审计日志。
- 审计日志至少保留 180 天。

## 6. 页面范围

1. 登录页。
2. 运营大盘。
3. 店铺与商品列表页。
4. 商品智能运营工作台：商品与 SKU、竞品与诊断、创意与脚本、生成任务与素材、投放与审批、数据与复盘。
5. 全局任务中心。
6. 批量导入中心。
7. 审批中心。
8. 系统管理页：用户、授权、模型服务、任务规则和审计日志。

一期以桌面端为主，支持宽度不低于 1280 px 的 Chrome 和 Edge 最新两个主要版本。

## 7. 非功能要求

- 在 20 个并发在线用户、10,000 个商品和 1,000,000 条经营数据记录规模下，普通接口 P95 不超过 2 秒。
- 运营大盘首次加载不超过 3 秒，不包含第三方 AI 服务耗时。
- 10,000 行文件在 2 分钟内完成校验和导入。
- 第三方 AI 服务不可用时，不影响商品、导入、经营数据和历史报告查询。
- 异步执行器重启后，未完成任务不得静默丢失。
- 数据库每日备份一次，备份保留 7 天，并提供恢复说明。
- 全部受保护接口进行服务端身份和权限校验。
- 密码安全散列存储，模型密钥加密存储。
- 禁止存储平台明文密码、Cookie、支付凭据及日志中的敏感信息。
- 上传文件校验扩展名、MIME 类型和大小。
- 日志包含请求 ID；任务日志包含任务 ID 和执行尝试 ID。

## 8. 交付要求

- 可运行的前端、后端和异步任务执行器源代码。
- 数据库迁移及示例数据初始化脚本。
- 离线模拟服务和三类 AI 服务适配器。
- 四类数据导入模板。
- API、部署、配置、备份和恢复文档。
- 不包含真实密钥的环境变量示例。
- 自动化测试和验收测试结果。
- 至少一个完整端到端场景的演示说明。

按照部署文档应能在 30 分钟内完成首次启动。没有第三方密钥时，仍能用模拟服务完成全部主流程。

## 9. 验收基线

1. 三类演示账号可登录且权限正确。
2. 可创建两个店铺、一个商品和三个 SKU，并触发库存预警。
3. 可为一个商品维护两个平台商品映射和至少两个竞品。
4. 可生成结构完整、可编辑、可版本追踪的商品诊断。
5. 一次生成不少于 3 组主图方案和 3 套视频脚本。
6. 可验证图片及视频任务成功、失败、超时、取消和重试。
7. 素材可提交审核、驳回、重新提交、批准、打标和归档。
8. 运营人员不能批准投放建议，运营主管可以批准或驳回。
9. 四类导入模板均可使用，错误行能定位并下载。
10. CTR、CVR、跳失率和 ROI 按本文公式正确计算。
11. 可生成、保存并导出包含数据限制和行动项的复盘报告。
12. 可完整演示一个商品从建档到下一轮诊断的业务闭环。
13. 未授权用户无法通过页面或接口访问其他店铺数据。
14. 页面、接口响应和日志中不出现完整密钥、明文密码、Cookie 或会话令牌。

## 10. 需求变更规则

- 真实平台同步、广告账户操作、竞品抓取或企业系统集成都属于范围变更，需要重新评估授权、合规、成本和工期。
- 指标定义、角色权限、任务状态或验收口径变更时，必须同步更新需求、PRD 和测试用例。
- 未在本文明确的能力不作为一期强制验收项。
